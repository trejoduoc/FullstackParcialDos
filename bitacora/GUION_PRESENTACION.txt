# GUION DE DEFENSA - NOMADICO OUTDOOR (Evaluación Parcial 2)

## 1. INTRODUCCIÓN Y CONCEPTO
"Buen día. Mi proyecto es 'Nomadico Outdoor', una tienda especializada en equipamiento para camping y senderismo. El núcleo del negocio es la economía circular, promoviendo el consumo responsable mediante el alquiler y la venta de productos reacondicionados."

## 2. MIGRACIÓN TECNOLÓGICA (HTML -> REACT)
"Para esta entrega, el cambio más importante fue la migración de un sitio web estático en HTML a una aplicación moderna utilizando React.
¿Por qué React?
1. Escalabilidad: Ahora el sitio se basa en Componentes Reutilizables.
2. Experiencia de Usuario: Al ser una SPA (Single Page Application), la navegación es instantánea sin recargar la página.
3. Mantenibilidad: Si necesito cambiar la estructura de una tarjeta de producto, lo hago en un solo archivo y se refleja en toda la tienda."

## 3. ARQUITECTURA DE COMPONENTES
"He aplicado el principio de 'Single Responsibility' (Responsabilidad Única).
- Componentes de Layout: Navbar y Footer, que se mantienen constantes en todas las vistas.
- Componentes de Vista: Home, ProductList, CategoryView y AdminPanel.
- Componentes Atómicos: ProductCard, que recibe la información del producto mediante 'Props' y la renderiza."

## 4. GESTIÓN DE DATOS Y PERSISTENCIA (CRUD)
"Para simular una base de datos real, implementé un 'Data Service' en JavaScript. Este servicio gestiona la persistencia de los datos mediante funciones CRUD:
- Create: Para añadir nuevos productos desde el panel de admin.
- Read: Para listar productos por categorías o filtrar ofertas.
- Update: Para modificar precios o stock.
- Delete: Para remover productos del catálogo."

## 5. DISEÑO RESPONSIVO CON BOOTSTRAP
"Para asegurar que la tienda sea accesible desde cualquier dispositivo, integré Bootstrap. Utilicé el sistema de 'Grid' (contenedores, filas y columnas), lo que permite que el diseño se adapte automáticamente si el usuario entra desde un móvil, una tablet o un PC."

## 6. CALIDAD Y TESTING (JASMINE & KARMA)
"La calidad del software se garantizó mediante pruebas unitarias utilizando Jasmine y Karma.
Me enfoqué en cuatro tipos de pruebas:
1. Renderizado: Verificar que los componentes se muestren correctamente con los datos recibidos.
2. Props: Asegurar que la información pase correctamente del padre al hijo.
3. Estado (State): Validar que los formularios cambien su valor mientras el usuario escribe.
4. Eventos: Simular clics en botones para comprobar que se ejecutan las funciones esperadas."

## 7. CONCLUSIÓN
"En resumen, el proyecto pasó de ser una maqueta visual a un sistema funcional con lógica de datos, diseño profesional responsivo y un proceso de testeo robusto, cumpliendo con los estándares de desarrollo frontend moderno."
